| Native Driver             | Mongoose                       |
| ------------------------- | ------------------------------ |
| Official MongoDB driver   | ODM built on top of the driver |
| Talks directly to MongoDB | Talks to the driver            |

| Lightweight               | Feature-rich                   |

4. Why was Mongoose created?

To provide application-level features such as:

Schema definitions
Validation
Middleware
Models
Virtuals
Plugins

without changing how MongoDB itself works.

Interview Questions ⭐
1. Does MongoDB have schemas?

Correct answer:

MongoDB supports a flexible (dynamic) schema by default, and it also supports optional schema validation. Mongoose adds application-level schemas on top of that.

2. Why does Mongoose use schemas?

To provide:

Consistent document structure
Validation
Better maintainability
Team-wide conventions
3. Who enforces a Mongoose schema?

Not MongoDB.

Your Node.js application does, before the request reaches the MongoDB server.

4. Is a Mongoose schema stored in MongoDB?

No.

A Mongoose schema exists in your application code.

MongoDB only stores the resulting documents.

Interview Questions ⭐
1. Is String in a Mongoose schema the same as MongoDB's BSON String?

Not exactly.

String is a Mongoose Schema Type. Mongoose maps it to the appropriate BSON type when writing to MongoDB.

2. Which schema type is used for relationships?
mongoose.Schema.Types.ObjectId

Usually with the ref option.

3. When should you use Decimal128 instead of Number?

When precision is critical, such as financial or monetary values.

4. Why avoid overusing Mixed?

Because you lose many of the benefits of schemas, such as validation and predictable structure.

"Mongoose first tries to cast the value according to the schema type. If casting succeeds, it proceeds. If casting fails, it throws a CastError and the document is not saved."

1. What is a Model?

A Model is a compiled version of a Schema that provides an interface for interacting with a MongoDB collection.

2. Can a Schema perform CRUD operations?

❌ No.

Only a Model can.

3. What does mongoose.model() do?

It compiles a Schema into a Model by attaching CRUD methods, validation, middleware, virtuals, plugins, and the connection to the MongoDB Native Driver.

4. Is a Model the same as a Collection?

No.

The Model exists in your Node.js application.

The Collection exists in MongoDB.

The Model represents the Collection.

5. Does new User() save data?

No.

It creates a Mongoose Document in memory.

You must call save() or use methods like create() to persist it.

=============================================================================================================
                                                   LEAN
==================================================================================================


1. What does lean() do?

It tells Mongoose to skip document hydration and return plain JavaScript objects instead of Mongoose documents.

2. Why is lean() faster?

Because Mongoose doesn't create document instances or attach document behavior such as change tracking and instance methods.

3. What do we lose with lean()?
Document methods (save(), etc.)
Change tracking
Virtuals (by default)
Getters/Setters (by default)
4. When should we use lean()?

Read-only queries where you only need data and won't modify or save the returned documents.

5. When should we avoid lean()?

When you need document behavior such as calling save(), relying on middleware tied to documents, or using document instance methods.
